# Définir et appeler une fonction

## Objectifs

- Définir une fonction avec le mot-clé `def`.
- Distinguer la **définition** d'une fonction de son **appel**.
- Comprendre pourquoi une fonction doit être définie avant d'être appelée.
- Faire appeler une fonction par une autre fonction.
- Suivre le déroulement de l'exécution d'un programme qui contient des fonctions.
- Choisir un bon nom de fonction.

## 1. Syntaxe

```python
def nom_de_la_fonction():
    # corps de la fonction : instructions exécutées à chaque appel
```

| Élément | Rôle |
| --- | --- |
| `def` | Mot-clé qui annonce la **définition** d'une fonction (*define*). |
| `nom_de_la_fonction` | Le nom choisi, selon les mêmes règles que pour une variable. |
| `()` | Les parenthèses, obligatoires. Elles accueilleront les paramètres (voir [7.3](7.3%20-%20Paramètres%20et%20arguments.md)). |
| `:` | Les deux-points, obligatoires, comme pour `if`, `while` et `for`. |
| Bloc indenté | Le **corps** de la fonction. Il se termine à la première ligne qui revient à la marge. |

### Premier exemple

La caisse du Café Le Binaire affiche un en-tête au début du menu et au début de la facture. Plutôt que d'écrire ces trois lignes deux fois, on en fait une fonction :

```python
NOM_CAFE = "Café Le Binaire"
LARGEUR_FACTURE = 34


def afficher_entete():
    print("=" * LARGEUR_FACTURE)
    print(f"{NOM_CAFE:^{LARGEUR_FACTURE}}")
    print("=" * LARGEUR_FACTURE)
```

> 💡 La largeur de l'en-tête est une constante, comme le nom du café. Dans un f-string, la largeur peut elle-même être une variable ou une constante : on la place entre accolades à l'intérieur du format. On imbrique donc les `{}` et Python les interpole des plus rapprochées aux plus éloignées.  
>
> Ainsi, l'expression `{NOM_CAFE:^{LARGEUR_FACTURE}}` va centrer le nom sur `LARGEUR_FACTURE` caractères, ce qui équivaut à `{NOM_CAFE:^34}` après la première interpolation.
>
> 💡 Par convention ([PEP 8](https://peps.python.org/pep-0008/#blank-lines)), on laisse **deux lignes vides** avant et après la définition d'une fonction. Cela la rend facile à repérer dans un fichier.

## 2. Définir n'est pas appeler

Exécuter le code ci-dessus **n'affiche rien**. La définition ne fait qu'**enregistrer** la fonction auprès de Python, comme une recette qu'on écrit dans un livre sans la cuisiner.

Pour exécuter le corps de la fonction, il faut l'**appeler** : on écrit son nom suivi de parenthèses.

```python
afficher_entete()
```

```text
==================================
         Café Le Binaire
==================================
```

On peut appeler une fonction autant de fois qu'on le souhaite. Son corps est exécuté **au complet** à chaque appel.

```python
afficher_entete()
print("Bienvenue!")
afficher_entete()
```

### Piège : oublier les parenthèses

```python
# ❌ Mauvais : aucune erreur, mais la fonction n'est pas exécutée!
afficher_entete
```

```python
# ✅ Bon : les parenthèses déclenchent l'appel
afficher_entete()
```

Sans parenthèses, on ne fait que **nommer** la fonction, sans la déclencher. Python ne signale aucune erreur, ce qui rend ce piège difficile à repérer.

## 3. Définir avant d'appeler

Python lit un fichier **de haut en bas**. Lorsqu'il rencontre un appel, la fonction doit déjà avoir été définie plus haut, sinon il ne la connaît pas encore.

```python
# ❌ Mauvais : l'appel arrive avant la définition
LARGEUR_FACTURE = 34

afficher_entete()

def afficher_entete():
    print("=" * LARGEUR_FACTURE)
```

```text
NameError: name 'afficher_entete' is not defined
```

```python
# ✅ Bon : la définition arrive d'abord
LARGEUR_FACTURE = 34

def afficher_entete():
    print("=" * LARGEUR_FACTURE)

afficher_entete()
```

> 📌 C'est pourquoi, dans un programme, on place **toutes les définitions de fonctions en haut**, et le code qui les utilise **en bas**. On y reviendra en [7.8 - Structurer un programme avec des fonctions](7.8%20-%20Structurer%20un%20programme%20avec%20des%20fonctions.md).

## 4. Une fonction peut en appeler une autre

Le corps d'une fonction peut contenir n'importe quelle instruction : des conditions, des boucles… et des appels à d'autres fonctions.

La fonction `afficher_menu()` réutilise `afficher_entete()`, puis affiche la liste des produits :

```python
NOM_CAFE = "Café Le Binaire"
PRODUITS = ("Café filtre", "Latté", "Chocolat chaud", "Muffin", "Biscuit")
PRIX = (2.25, 4.50, 3.75, 3.25, 1.95)
LARGEUR_FACTURE = 34


def afficher_entete():
    print("=" * LARGEUR_FACTURE)
    print(f"{NOM_CAFE:^{LARGEUR_FACTURE}}")
    print("=" * LARGEUR_FACTURE)


def afficher_menu():
    afficher_entete()
    for i in range(len(PRODUITS)):
        print(f"{i + 1}. {PRODUITS[i]:<20}{PRIX[i]:>9.2f} $")
    print("0. Terminer la commande")


afficher_menu()
```

```text
==================================
         Café Le Binaire
==================================
1. Café filtre              2.25 $
2. Latté                    4.50 $
3. Chocolat chaud           3.75 $
4. Muffin                   3.25 $
5. Biscuit                  1.95 $
0. Terminer la commande
```

> 💡 Ici, `afficher_entete()` est définie **avant** `afficher_menu()`. Ce n'est pourtant pas obligatoire : ce qui compte, c'est que les deux soient définies avant le **premier appel**, `afficher_menu()`, tout en bas.

## 5. Le déroulement de l'exécution

Quand Python rencontre un appel, il **saute** au début du corps de la fonction, l'exécute au complet, puis **revient** exactement là où il était pour continuer.

Voici l'ordre dans lequel s'exécute le programme précédent :

```text
① def afficher_entete():   → Python mémorise la fonction (rien n'est exécuté)
② def afficher_menu():     → Python mémorise la fonction (rien n'est exécuté)
③ afficher_menu()          → saut dans afficher_menu()
   ④ afficher_entete()     →   saut dans afficher_entete()
      ⑤ print("=" * LARGEUR_FACTURE)
      ⑥ print(f"{NOM_CAFE:^{LARGEUR_FACTURE}}")
      ⑦ print("=" * LARGEUR_FACTURE)  →   fin : retour dans afficher_menu()
   ⑧ for i in range(...)   →   affiche les 5 produits
   ⑨ print("0. Terminer la commande")  → fin : retour au programme
⑩ fin du programme
```

> 💡 Le débogueur de VS Code permet de voir ce va-et-vient en direct : place un point d'arrêt (`F9`) sur l'appel, démarre le débogage (`F5`), puis avance avec **Pas à pas détaillé** (`F11`) pour entrer dans la fonction. Voir [Raccourcis VS Code](../Outils/Raccourcis%20VS%20Code.md).

## 6. Nommer une fonction

Les règles sont les mêmes que pour les variables (voir [2.2 - Variables](../Cours%2002/2.2%20-%20Variables.md)) : lettres minuscules, chiffres et soulignements, en `snake_case`.

Comme une fonction **fait** quelque chose, son nom commence idéalement par un **verbe** à l'infinitif.

| ❌ À éviter | ✅ Mieux | Pourquoi |
| --- | --- | --- |
| `entete()` | `afficher_entete()` | Le verbe dit ce que fait la fonction. |
| `taxes()` | `calculer_taxes()` | On sait qu'elle *calcule* quelque chose. |
| `f1()`, `truc()` | `lire_entier()` | Le nom doit être significatif. |
| `AfficherMenu()` | `afficher_menu()` | Convention `snake_case`. |
| `print()`, `sum()` | `afficher_facture()`, `calculer_sous_total()` | Ne jamais réutiliser le nom d'une fonction de Python : on la rendrait inutilisable. |

## 7. Bonnes pratiques

### Une fonction, une tâche

Une fonction doit faire **une seule chose**, et la faire bien. Si on a du mal à la nommer sans utiliser « et » (`afficher_menu_et_calculer_total()`), c'est le signe qu'il faut la découper en deux fonctions.

### Préparer un squelette avec `pass`

Le corps d'une fonction ne peut pas être vide. Pour planifier un programme avant de l'écrire, on peut créer des fonctions « vides » avec le mot-clé `pass`, qui ne fait rien :

```python
def afficher_menu():
    pass    # à compléter


def afficher_facture():
    pass    # à compléter
```

Le programme s'exécute sans erreur, et on remplit chaque fonction une à une.

## En résumé

- On **définit** une fonction avec `def nom():` suivi d'un bloc indenté.
- Définir une fonction ne l'exécute pas : il faut l'**appeler** avec `nom()`, sans oublier les parenthèses.
- Une fonction doit être définie **avant** d'être appelée, sinon : `NameError`.
- Une fonction peut appeler d'autres fonctions; après chaque appel, l'exécution **revient** là où elle était.
- Un nom de fonction est en `snake_case` et commence idéalement par un verbe.
